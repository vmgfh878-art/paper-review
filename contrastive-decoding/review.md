## 1. 한 줄 요약

디코딩 단계에서 큰 모델(전문가)과 작은 모델(아마추어)의 확률을 대조해
토큰을 고르는 방법. 추가 학습 없이 반복을 줄이면서 일관성을 유지한다.

## 2. 배경 — 이 논문이 나오기까지

디코딩 방법은 크게 두 갈래로 나뉜다.

```
탐색형 (최대화)    greedy, beam              →  반복 문제
샘플링형 (무작위)   top-k, nucleus, typical   →  일관성 깨짐
```

계보를 따라가면 이렇게 된다.

```
greedy / beam       →  top-k (2018)  →  nucleus (2019)  →  CD (2022)
   반복 문제           무작위성 도입      적응형 컷오프      탐색으로 회귀
```

**top-k의 한계가 nucleus를 낳았다.** k가 고정이라 분포 모양에 맞추지 못한다.

```
분포가 뾰족할 때 (다음 단어가 거의 정해짐)
  k=50 → 쓸모없는 후보까지 억지로 포함

분포가 평평할 때 (뭐가 와도 되는 자리)
  k=50 → 괜찮은 후보를 잘라냄
```

nucleus는 개수 대신 누적확률 p까지 자른다. 분포가 뾰족하면 후보가 적고
평평하면 많아지는 **적응형 컷오프**다.

> nucleus를 제안한 Ari Holtzman이 이 논문의 2저자다.
> 샘플링을 만든 사람이 "샘플링 말고 다른 길"을 제안한 셈이다.

**이 흐름이 CD의 설계로 이어진다.** "고정 컷오프는 분포 모양에 맞출 수 없다"는
교훈이 CD의 타당성 제약에 그대로 반영되어 있다.

```
top-k:    상위 k개              고정 개수  → 분포 무시
nucleus:  누적확률 p까지         적응형
CD:       전문가 최고확률 × α 이상  적응형
```

CD의 제약 이름이 **Adaptive Plausibility Constraint**인 이유다.
α=0.1은 절대 확률값이 아니라 1등 대비 비율이므로 분포 모양을 따라간다.

## 3. 기존 방식의 한계

**문제 1 — 탐색형은 반복한다**

greedy나 beam은 확률이 가장 높은 것만 이어 붙인다. 그 결과 짧고 반복적인
글이 나온다. 논문은 "최대확률은 개방형 생성에서 나쁜 목적함수"라고 정리한다.

**문제 2 — top-k의 고정 컷오프는 분포 모양에 맞지 않는다**

k가 고정이라 분포가 뾰족하든 평평하든 무조건 k개를 후보로 삼는다.

```
뾰족한 분포 → 쓸모없는 후보까지 억지로 포함
평평한 분포 → 괜찮은 후보를 잘라냄
```

nucleus(top-p)가 이걸 고쳤다. 확률 높은 순으로 담다가 누적이 p를 넘으면 멈춘다.

```
p = 0.95

평평한 분포   확률: 0.20 0.18 0.17 0.15 0.15 0.15
              누적: 0.20 0.38 0.55 0.70 0.85 1.00  → 후보 6개

뾰족한 분포   확률: 0.90 0.05 0.03 0.02
              누적: 0.90 0.95 0.98 1.00            → 후보 2개
```

같은 p인데 후보 개수가 분포에 따라 달라진다. 이것이 적응형 컷오프다.

**문제 3 — 컷오프를 고쳐도 무작위성 자체가 남는다** ★

이것이 CD가 겨냥하는 진짜 지점이다. 후보를 잘 골라도 결국 **그 안에서
주사위를 굴린다.** 후보가 많아지는 평평한 분포에서는 엉뚱한 토큰이 걸릴
확률이 함께 올라간다.

문제는 여기서 끝나지 않는다. 언어모델은 자기가 뱉은 토큰을 다시 입력으로
받으므로(auto-regressive), **한 번의 실수가 되돌려지지 않는다.**

```
256개 토큰 생성 = 주사위를 256번 굴림

한 번 이상한 토큰이 걸림
    ↓
모델은 그것을 이미 정해진 사실로 받아들임
    ↓
거기서부터 자연스럽게 이어감  ← 되돌아오지 않음
    ↓
주제 이탈
```

Table 3의 소닉 예시가 이 현상이다. nucleus는 게임 이야기를 하다 한 번 새고,
그 뒤로는 샌 채로 유창하게 계속 쓴다. **문장 하나하나는 멀쩡한데 전체가 딴 얘기가 된다.**

인간평가에서 유창성은 1.4배 차이인데 일관성은 2.6배로 벌어지는 이유다.
샘플링이 못 쓰는 것이 아니라, 긴 글에서 방향을 잃는 것이다.

| | 탐색형 (greedy/beam) | 샘플링형 (top-k/nucleus) | CD |
|---|---|---|---|
| 다양성 | 낮음 (반복) | 높음 | 높음 |
| 일관성 | 높음 | 낮음 (주제 이탈) | 높음 |
| 무작위성 | 없음 | 있음 | 없음 |

**CD의 답은 컷오프를 더 잘 잡는 것이 아니라 주사위를 아예 안 굴리는 것이다.**
목적함수를 고쳐서 결정론적으로 고른다. 제목의 *as Optimization*이 이 뜻이고,
7.3에서 탐색이 샘플링보다 낫다는 결과로 확인된다.

## 4. 핵심 아이디어

전제는 하나다.

> **큰 모델의 실패는 작은 모델에서 더 심하게 나타난다.**

반복이나 횡설수설은 실패다. 따라서 아마추어가 그런 토큰에 **더 높은** 확률을 준다.
두 확률을 빼면 실패 패턴이 상쇄되고, 전문가만 아는 좋은 표현이 남는다.

```
프롬프트: "오바마는 하와이에서 태어났다. 그는 ___에서 태어났다"

후보 "Hawaii" (반복)
  전문가   0.30      전문가도 반복 성향이 있다
  아마추어  0.60      아마추어는 더 심하다
  log 0.30 − log 0.60 = log(0.5) = −0.69      탈락

후보 "1961" (좋은 답)
  전문가   0.20      전문가는 이것을 알아본다
  아마추어  0.02      아마추어는 모른다
  log 0.20 − log 0.02 = log(10)  = +2.30      선택
```

**결정적인 부분**: `1961`의 전문가 확률(0.20)이 `Hawaii`(0.30)보다 낮다.

```
최대확률로 고르면  →  Hawaii  (0.30 > 0.20)    반복 발생
CD로 고르면       →  1961    (+2.30 > −0.69)  정답
```

**확률 1등이 아닌 것을 뽑아내는 것**이 CD가 하는 일이다.
아마추어가 "이건 나도 안다"고 말하는 뻔한 선택지를 걷어낸다.

> 7.1에서 3-gram 아마추어가 실패한 이유가 여기 있다. 아마추어가 **같은 방식으로
> 실패**해야 반복 토큰에 높은 확률을 주고, 그래야 뺄셈으로 상쇄된다.
> n-gram은 실패 방식이 달라 이 상쇄가 일어나지 않는다.

### 화용론적 해석 (4장)

화용론은 "말의 뜻"이 아니라 **"이 말을 왜 골랐는가"** 를 다룬다.
핵심 원리는 **좋은 화자는 자기 의도를 다른 가능성과 구별되게 말한다**는 것이다.

```
누군가를 소개할 때

"사람이에요"           → 누구나 해당. 정보량 0
"왼손잡이 첼리스트예요"  → 특정됨. 정보량 큼
```

둘 다 참인데 뒤엣것만 정보를 준다. **아무나 할 수 있는 말은 정보가 없다.**

CD에 대입하면 이렇게 된다.

```
아마추어도 높게 주는 토큰  =  누구나 할 수 있는 말   =  정보 없음
전문가만 높게 주는 토큰    =  전문가만 할 수 있는 말  =  정보 있음
```

읽으면서 "독창성을 강조한다"고 느껴지는 부분이 이것이다.
CD는 독창성을 따로 추구하지 않는다. **아마추어를 빼는 행위 자체가 뻔한 말을
제거하는 것**이고, 그 결과가 독창성으로 나타난다.

논문이 이 절을 넣은 이유는, "두 모델 확률 빼기"라는 임시방편처럼 보이는 계산에
이론적 근거를 주기 위해서다. 소통 이론에서 보면 자연스러운 연산이라는 것이다.

## 5. 구조 / 방법

토큰 하나를 고르는 절차는 다음과 같다.

```
1. 전문가에게 다음 토큰 확률 분포를 받는다
        ↓
2. V_head 확정  ← 전문가 최고확률 × α(0.1) 이상만 남김
        ↓         (전문가 혼자 결정한다)
3. 아마추어에게도 같은 문맥으로 확률을 받는다  (온도 τ 적용)
        ↓
4. 후보들에 대해  log p_전문가 − log p_아마추어  계산
        ↓
5. 명단 밖은 −∞ 처리
        ↓
6. 점수 최고인 토큰 선택   ← 주사위를 굴리지 않는다
```

이것을 빔서치(폭 5)로 누적하며 256토큰까지 반복한다.
로그를 쓰므로 점수가 덧셈으로 쌓이고, 그래서 빔서치가 가능하다.

**주의할 점 — 제약은 전문가 확률만으로 정해진다.**

```
V_head = { x : p_전문가(x) ≥ α · max p_전문가 }
              └──────────────────────────┘
                    아마추어가 들어가지 않는다
```

제약은 뺄셈 결과에 의존하지 않는 **독립적인 문지기**다.
CD 점수를 보고 이상한 것을 걸러내는 것이 아니라, 전문가가 혼자 후보 명단을
먼저 확정한다. 뺄셈 점수가 아무리 높아도 명단에 없으면 선택될 수 없다.

> 수식이 조건부 형태(V_head 안이면 점수, 밖이면 −∞)라서 "빼고 나서 마스킹"으로
> 읽어도 결과는 같다. 중요한 것은 **선택 이전에 걸러진다**는 점이다.

## 6. 주요 구성 요소

### 6-1. 대조 목적함수 (3.1)

```
log p_전문가(x) − log p_아마추어(x)
```

로그의 뺄셈은 확률의 나눗셈과 같다. 직관적으로는
**전문가가 아마추어보다 이 단어를 몇 배나 더 좋아하는가**를 보는 것이다.

로그로 쓰는 이유는 세 가지다.

1. 언어모델이 원래 로그확률을 내놓는다. 확률을 그대로 곱하면 언더플로가 난다.
2. 문장 전체 점수가 덧셈이 되어 토큰 단위로 누적할 수 있다 → 빔서치가 가능해진다.
3. 직관은 "비율"로 보는 편이 편하다.

### 6-2. 타당성 제약 V_head (3.2)

```
V_head = { x : p_전문가(x) ≥ α · max p_전문가 },   α = 0.1
```

목적함수만으로는 작동하지 않는다. 분모인 아마추어 확률이 아주 작을 때 비율이
폭발해서, **전문가도 좋아하지 않는 토큰이 1등**이 되기 때문이다.

α는 절대 확률값이 아니라 **1등 대비 비율**이므로 분포 모양을 따라간다.
top-k의 고정 컷오프 문제를 피한 설계이고, 이름이
**Adaptive** Plausibility Constraint인 이유다. (2장 참고)

### 6-3. 아마추어 설계 — 일부러 나쁘게 만든다

아마추어를 다루는 세 장치가 모두 같은 방향을 향한다.

| 장치 | 내용 | 효과 |
|---|---|---|
| 크기 (7.1) | 가능한 한 작은 모델 | 격차가 클수록 품질 향상 |
| 온도 (7.2) | τ를 낮춰 분포를 뾰족하게 | 나쁜 선택을 확신하게 만듦 |
| 맥락 (7.5) | 전체 대신 최근 토큰만 | 일관성을 떨어뜨림 |

**전부 아마추어를 더 나쁘게 만드는 조치다.**

아마추어는 "실패의 표본" 역할이므로, 실패가 선명할수록 깨끗하게 상쇄된다.
반대 극단을 보면 분명해진다.

```
아마추어가 균등분포(완전히 평평)라면?
→ 모든 토큰에서 같은 값을 빼는 것
→ 순위가 바뀌지 않음
→ 그냥 최대확률 디코딩 = 반복 발생
```

**균등분포를 빼는 것은 아무것도 빼지 않는 것과 같다.**
7.2에서 τ를 키우면 반복적인 텍스트로 되돌아가는 이유가 이것이다.

```
τ 작게 → 아마추어가 나쁜 선택을 확신 → 뺄 대상이 선명
τ 크게 → 아마추어가 밋밋해짐         → 뺄 것이 없어짐
```

단, 아무 모델이나 나쁘면 되는 것은 아니다. 아마추어는 **전문가와 같은 방식으로
실패**해야 한다. (7.1의 3-gram 실패, 4장 참고)

## 7. 실험 결과

**설정** — 위키(WikiText-103), 뉴스(Wikinews), 소설(BookCorpus) 세 도메인.
32단어 프롬프트를 주고 256토큰을 생성한다.
비교 대상은 greedy, top-k(k=50), nucleus(p=0.95), typical(τ=0.95),
그리고 이름이 비슷하지만 다른 방법인 Contrastive Search.

모델 쌍은 GPT-2 XL(1.5B)/small(100M), OPT-13B/125M, OPT-6.7B/125M.
전문가와 아마추어가 **같은 계열**이다. α=0.1로 전 실험 고정, 빔 폭 5.

### 7-1. 자동평가 (Table 1)

CD (OPT-13B 기준)

| 도메인 | diversity | MAUVE | coherence |
|---|---|---|---|
| 뉴스 | 0.94 | 0.94 | 0.69 |
| 위키 | 0.91 | 0.91 | 0.69 |
| 소설 | 0.89 | 0.94 | 0.62 |

읽어야 할 패턴은 두 가지다.

1. **MAUVE와 coherence는 세 도메인 모두에서 baseline을 앞선다.**
2. **diversity는 샘플링 방법들과 대등하거나 약간 낮다.**

두 번째가 오히려 성과다.

```
greedy / beam (결정론적)  →  다양성 바닥 (반복)
샘플링 (무작위)           →  다양성 높음 (주사위를 굴리니 당연)
CD (결정론적)            →  다양성이 샘플링급   ← 이례적
```

주사위를 굴리지 않으면 반복에 빠지는 것이 정상이다.
CD는 **무작위성 없이 목적함수만으로 반복을 잡았다.**
이 논문의 주장은 다양성 1위가 아니라, 다양성을 지키면서 일관성을 얻었다는 것이다.

### 7-2. 인간평가 (Table 2)

| | CD 선호 배수 |
|---|---|
| 일관성 vs nucleus | 2.6배 |
| 일관성 vs typical | 6.4배 |
| 유창성 vs nucleus | 1.4배 |
| 유창성 vs typical | 3.5배 |

자동 지표보다 사람 평가에서 격차가 더 크다. 특히 일관성에서 벌어진다.
문장 단위 품질(유창성)보다 **글 전체의 방향**에서 차이가 난다는 뜻이다.

### 7-3. 정성 예시 (Table 3)

소닉 더 헤지호그 게임에 대한 이어쓰기. nucleus는 게임 이야기를 하다 무관한
내용으로 새고 글의 형식까지 바뀐다. CD는 기술적 세부사항을 유지하며 이어간다.
coherence 수치가 실제로 무엇을 의미하는지 보여주는 예시다.

### 7-4. Ablation (7장)

**① 타당성 제약이 없으면 붕괴한다 (Table 4)**

| | MAUVE | coherence |
|---|---|---|
| CD | 0.92 | 0.69 |
| CD − V_head | **0.01** | 0.23 |

성능이 낮아지는 정도가 아니라 완전히 무너진다.
**논문의 기여가 목적함수 하나가 아니라 목적함수와 제약의 조합**임을 보여주는 근거.

**② 아마추어는 같은 방식으로 실패해야 한다 (7.1, Figure 2)**

- 전문가와 아마추어의 크기 격차가 클수록 품질이 좋아진다
- 같은 모델끼리 대조하면 뺄 것이 없어 반복적인 텍스트가 나온다
- **3-gram을 아마추어로 쓰면 MAUVE 0.73으로 나빠진다**

n-gram은 앞 두 단어만 보는 통계 모델이라 실패 방식 자체가 다르다.
아마추어는 단순히 성능이 낮은 모델이 아니라, 전문가와 **같은 방식으로 실패하는**
모델이어야 한다.

**③ 탐색이 샘플링보다 낫다 (7.3, Table 4)**

| | diversity | MAUVE | coherence |
|---|---|---|---|
| CD (탐색) | 0.89 | 0.92 | 0.69 |
| CD (샘플링) | 0.81 | 0.85 | 0.68 |

nucleus와 top-k가 모두 샘플링 방식이라는 점에서 의미가 있다.
기존 통념은 "좋은 글을 얻으려면 무작위성이 필요하다"였는데,
이 논문은 **목적함수를 제대로 고치면 무작위성이 필요 없다**고 답한다.
제목의 *as Optimization*이 이 뜻이다.

**④ 아마추어 온도 (7.2)** — τ ∈ [0.5, 1.5]에서 안정적.
GPT-2는 0.5, OPT는 1.0을 썼다. (6-3 참고)

## 8. 한계와 후속

### 8-1. 한계

**① 개방형 생성에만 통한다**

위키, 뉴스, 소설 이어쓰기처럼 정답이 열려 있는 과제에서만 작동한다.
요약이나 번역 같은 과제 지향 생성에는 바로 적용되지 않는다.

```
개방형    : 작은 모델이 눈에 띄게 못함  →  뺄 것이 있음
요약/번역 : 둘 다 그럭저럭 해냄        →  뺄 것이 없음
```

실제로 요약에서 작은 요약 모델을 아마추어로 쓰면 **균등분포를 쓰는 것보다도
ROUGE가 낮았다.** 6-3에서 본 "균등분포를 빼는 것은 아무것도 빼지 않는 것"보다
더 나빴다는 뜻이다.

**② 추론할 때 모델을 두 개 돌려야 한다** — 비용과 메모리 부담.

**③ 아마추어 선택에 성능이 좌우된다** — 크기, 온도, 맥락 범위에 민감하고,
전문가와 같은 계열이어야 한다. (6-3)

**④ 성능 상한이 전문가에 묶인다** — CD는 전문가가 모르는 것을 만들어내지 못한다.
전문가가 알지만 확률 1등으로 올리지 못한 답을 끌어올릴 뿐이다.

### 8-2. 한계 ↔ 후속

| 한계 | 해결 방향 / 후속 |
|---|---|
| 모델 두 개 필요, 같은 계열 제약 | **DoLa** (Chuang et al., ICLR 2024) — 한 모델 안에서 최종 층 vs 초기 층 대조 |
| 개방형 생성에만 통함 | **CD Improves Reasoning** (O'Brien & Lewis, 2023) — 추론 과제로 확장 |
| 아마추어를 구해와야 함 | **ICD** (2024) — 환각을 의도적으로 유도해 약한 모델을 만들어냄 |
| 성능 상한이 전문가에 묶임 | 미해결 |

**DoLa** — https://arxiv.org/abs/2309.03883

```
CD:    큰 모델        vs  작은 모델         모델 2개 필요
DoLa:  최종 층(성숙)  vs  초기 층(미성숙)   모델 1개면 됨
```

아마추어를 밖에서 구해오지 않고 **모델 내부에서 만들어낸다.**
초기 층은 아직 덜 처리된 상태라 자연스럽게 아마추어 역할을 한다.
추론 비용과 계열 제약이 동시에 풀린다.

> CD 저자들이 9장 Future Work에서 제안한 **"같은 모델의 초기 체크포인트와
> 후기 체크포인트를 대조"** 아이디어가, 체크포인트 대신 **층**으로 실현된 것이다.

**CD Improves Reasoning** — https://arxiv.org/abs/2309.09117

원논문 공저자 Mike Lewis가 직접 낸 후속이다. 정답이 있는 추론 과제에 CD를 적용했다.

- LLaMA-65B가 HellaSwag(상식추론)에서 LLaMA 2, GPT-3.5, PaLM 2-L을 능가
- GSM8K(수학 문장제)에서도 GPT-3.5, PaLM-540B를 능가
- CD가 추상적 추론 오류와 입력 복사 같은 단순 실패를 막아준다는 분석

원논문의 "개방형에만 통한다"는 한계를 부분적으로 뒤집은 결과다.

그 외에 시각-언어 모델의 환각 억제(VCD 계열), 층 선택을 자동화하는 연구들이
이어지고 있다.

## 9. 남은 질문 / 아쉬운 점

**읽으면서 걸렸던 것**

- **nucleus(top-p)를 처음에 이해하지 못했다.** top-k와의 차이가
  "개수로 자르느냐(50개) 무게로 자르느냐(누적 95%)"라는 걸 잡고 나서 풀렸다.
  분포가 뾰족하면 후보가 적고 평평하면 많아지는 적응형이라는 점이 핵심.

- **Figure 1에서 전문가/아마추어의 확률 방향을 반대로 잡았다.**
  반복 토큰에 대해 "둘 다 낮게 준다"고 생각했는데, 실제로는 **둘 다 높게 주고
  아마추어가 더 높게** 준다. 반복은 실패이고, 실패는 작은 모델에서 더 심하기
  때문이다. 전제("큰 모델의 실패는 작은 모델에서 더 심하다")를 놓치면
  전체가 뒤집힌다.

- **4장 화용론을 급하게 넘겼다.** "독창성 강조"로만 읽혔는데,
  아무나 할 수 있는 말은 정보가 없다는 원리였다. CD는 독창성을 따로 추구하는
  것이 아니라 뻔한 말을 제거한 결과가 독창성으로 나타난다.

**논문이 답해주지 않는 것**

- **왜 하필 α = 0.1인가.** 7.4 ablation은 제약의 유무만 비교하고(0.92 vs 0.01)
  값 자체의 민감도는 다루지 않는다. 전 실험에 0.1을 고정했으므로
  "튜닝 없이 잘 된다"는 주장은 되지만 근거는 경험적이다.

- **왜 빔 폭이 5인가.** 관례적인 값으로 보이는데 근거 설명이 없다.
  빔 폭을 키우면 오히려 품질이 떨어지는 현상이 알려져 있어 더 궁금하다.

- **성능 상한이 전문가에 묶이는 문제.** CD는 전문가가 모르는 것을 만들어내지
  못한다. 이 제약을 넘는 방향이 있는지는 다루지 않는다.

## [선택] 배경 지식 정리

| 용어 | 뜻 | 왜 중요한가 |
|---|---|---|
| n-gram | 연속된 n개 단어 묶음. n-gram 모델은 앞 n−1개만 보고 다음을 예측하는 통계 모델 | 7.1에서 3-gram 아마추어가 실패한 이유 — 실패 방식이 Transformer와 다르다 |
| greedy | 매 스텝 확률 1등만 고르고 확정 | 반복 문제의 대표 |
| beam search | 매 스텝 유망한 경로 k개를 살려두고 누적 점수로 비교 | 당장 1등이 아니어도 나중에 좋아질 길을 남긴다. CD는 폭 5 |
| top-k | 상위 k개를 후보로 (개수로 자름) | 분포 모양을 무시한다 |
| nucleus (top-p) | 누적확률 p까지를 후보로 (무게로 자름) | 분포에 따라 후보 수가 자동 조절 = 적응형 |
| temperature τ | 분포의 뾰족함 조절. 낮으면 뾰족, 높으면 평평 | CD는 아마추어에 낮은 τ를 걸어 나쁜 습관을 선명하게 만든다 |
| diversity | 2~4-gram의 고유 비율을 곱한 값 | 높을수록 반복이 적다 |
| MAUVE | 생성 텍스트 분포와 사람 글 분포의 유사도 | 종합 점수 성격. 7.4의 0.01은 완전 붕괴를 뜻한다 |
| coherence | 프롬프트와 생성문의 문장 임베딩 코사인 유사도 (SimCSE) | 주제 유지 여부 |
| ROUGE | 요약 평가 지표. 정답 요약과 n-gram이 얼마나 겹치는가 | Limitations에서 요약 과제 실패를 보일 때 등장 |

## [선택] 수학

**① 대조 목적함수**

```
L_CD = log p_전문가(x) − log p_아마추어(x)
```

로그의 뺄셈 = 확률의 나눗셈. 직관은 "전문가가 아마추어보다 몇 배 더 좋아하는가".

```
log(a / b) = log a − log b
```

로그를 쓰는 이유
1. 언어모델이 원래 로그확률을 내놓는다 (확률을 곱하면 언더플로)
2. 문장 전체 점수가 덧셈이 되어 빔서치가 가능해진다
3. 직관은 비율로 보는 편이 편하다

**② 타당성 제약**

```
V_head(x_<i) = { x : p_전문가(x) ≥ α · max_w p_전문가(w) },   α = 0.1
```

절대 확률값이 아니라 **1등 대비 비율**이므로 문턱이 분포를 따라 움직인다.

```
뾰족한 분포  최고 0.9  →  문턱 0.09  →  후보 적음
평평한 분포  최고 0.2  →  문턱 0.02  →  후보 많음
```

극단값 확인
```
α 크게 (0.5)   →  문턱 높음  →  후보 적음  →  greedy에 가까워짐 (반복)
α 작게 (0.01)  →  문턱 낮음  →  후보 많음  →  제약이 무력화
```

**③ 최종 점수**

```
score(x_i) = log( p_전문가(x_i) / p_아마추어(x_i) )   if x_i ∈ V_head
           = −∞                                      otherwise
```

두 요소가 세트로 작동한다. ②가 빠지면 분모가 아주 작을 때 비율이 폭발해
전문가도 싫어하는 토큰이 1등이 된다. (7.4: MAUVE 0.92 → 0.01)
